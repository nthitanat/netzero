# NetZero coding entry point

For NetZero Node.js API, React, and related deployment work, use `docs/GENERAL_ARCHITECTURE.md` as the shared architecture guide, then the relevant client or server guide under `docs/client/` or `docs/server/`. The project does not adopt a separate architecture skill. The guides describe target boundaries and exceptions; they do not authorize application refactoring or deployment.

Read the affected side's `docs/client/architecture-logs/CURRENT.md` or `docs/server/architecture-logs/CURRENT.md` when starting/resuming and only relevant linked records; read both for cross-stack work. Inspect actual working state. For implementation, resume/create a plan in that side's `implementation-plans/` and update its compact `CURRENT.md`. After code changes, record tested results or an in-progress checkpoint in that side's `architecture-logs/code-changes/` and update the architecture index. For cross-stack work, choose one primary owner and link the canonical record from both sides' indexes. Keep unrelated uncommitted work intact. Review-only tasks do not scaffold implementation records.

Use relevant sections of `docs/GENERAL_ARCHITECTURE.md` for NetZero boundaries/contracts; small styling/text edits need only applicable UI conventions and affected callers. For Glocal client implementation, read `docs/client/glocal/client-react-architecture.md` first. The shared guide owns `/api/v1` compatibility, mysql2 pagination bindings, function/naming conventions, per-table seeds, image metadata cutovers, and project exceptions. Docker/deployment changes require relevant `docs/server/DOCKER-AND-DEPLOYMENT-GUIDE.md` sections and affected Compose files, scripts, and environment examples. Keep operator procedures in that existing guide; update affected guidance in place.

After testing a feature, ask which durable project rule, if any, the user wants added to the guide, unless already specified. Record approved rule changes in the owning side's `architecture-logs/rule-updates/`; link shared boundary rules from both sides' indexes. Keep `docs/GENERAL_ARCHITECTURE.md` directly in top-level `docs/`. Other new workflow Markdown belongs only in the matching `docs/client/` or `docs/server/` implementation and architecture record folders; do not add it under `netzero-server/docs/`. Keep secrets and sensitive raw data out of records.
